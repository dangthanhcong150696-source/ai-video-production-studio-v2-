# Studio V3.2 — saved projects, bundles, character lock

V3.2 extends the V3.1 server (`server/index.mjs`, `server/media.mjs`) with four identifiable pieces:

| Workstream | Code |
| --- | --- |
| 1. Storage | `server/storage/` — local directory, Google Drive, zip bundles |
| 2. Manifest and API | `server/manifest.mjs`, `server/v32.mjs` |
| 3. Character lock | `server/character.mjs`, `src/CharacterLock.tsx` |
| 4. QC | `tests/v3-2-qc.test.mjs`, `docs/V3_2_QC_REPORT.md` |

`render.yaml` is unchanged. This branch does not deploy and does not modify the existing Render service. No paid API and no AI generation call is added.

## Run locally

Node 22+, FFmpeg and FFprobe with libx264/AAC. No API key.

```sh
npm ci --ignore-scripts
npm run build
npm start
```

Development with the Vite UI:

```sh
npm run dev
```

Vite on port 5173 proxies `/api` to the backend on port 3001. `npm start` serves the built UI and the API on `PORT` (default 3001), bound to `0.0.0.0`.

| Variable | Role |
| --- | --- |
| `DATA_DIR` | Live projects. Default `data-v3/`. Ephemeral on a free host. |
| `SAVE_DIR` | Durable local saves. Default `saves-v3/`, outside `DATA_DIR`. |
| `STORAGE_BACKEND` | `local` (default) or `drive`. |
| `STUDIO_PASSWORD` | Optional HTTP Basic Auth. Username `studio`. `/api/health` stays public. |

A project id is listed by `GET /api/projects`. The browser still remembers the last id, and it also reloads from that list when localStorage is empty. Saving sets `persisted: true`, which the 6-hour cleanup skips. After the live disk is wiped, `POST /api/saved/:id/restore` or a bundle upload rebuilds the project, checks every sha256, and refuses the restore if anything is missing or different.

## Manifest

`manifest.json` is schema version **1**.

- `manifestVersion`, `studio`, `appVersion`, `savedAt`
- `project`: id, name, timestamps, source info (duration, size, fps, audio, sha256, mime)
- `project.scenes[]`: 0-based `id`, plus `media[]` with `role`, `path`, `sha256`, `size`, `mime`
- `project.timeline[]`: `sceneId`, `start`, `duration` in scene order
- `project.characterLock`: the character record, or absent
- `project.lastExport`: probe of `output.mp4` when a render exists
- `files[]`: every byte the restore must verify

## HTTP

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/projects` | Live projects on this instance |
| POST | `/api/projects/:id/save` | Save to `local` or `drive` (`{"backend":"local"}`) |
| GET | `/api/saved?backend=local` | List saved projects |
| POST | `/api/saved/:id/restore` | Restore a saved project into `DATA_DIR` |
| GET | `/api/projects/:id/bundle` | Download a `.zip` of the live project |
| GET | `/api/saved/:id/bundle` | Download a `.zip` from storage |
| POST | `/api/bundles` | Upload a `.zip` (`bundle` field, max 256 MB) and restore it |
| GET | `/api/storage` | Local and Drive configuration. Drive is `configured: false` when env is missing |
| POST | `/api/characters` | Create a character. `rightsStatus` is required |
| POST | `/api/projects/:id/character` | Attach `{ "characterId" }` |

A bundle is a zip with `manifest.json` at the root and media under `media/`. STORE and DEFLATE are both accepted, so a bundle can be parked in Drive by hand and uploaded later. A sha256 mismatch returns **409** with `mismatches[]` and does not replace the live project.

## Google Drive

Drive stays **unconfigured** until both a target folder and credentials are present. Save and list then return **424** with `configured: false`. They do not invent a success result.

Service account:

```sh
GOOGLE_DRIVE_FOLDER_ID=the-folder-id
GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON='{"client_email":"...","private_key":"..."}'
# or a file, or the same JSON base64-encoded
GOOGLE_DRIVE_SERVICE_ACCOUNT_FILE=/secrets/studio-drive.json
STORAGE_BACKEND=drive
```

Share the target folder with the service-account `client_email` as Editor. The token scope is `https://www.googleapis.com/auth/drive`. `drive.file` cannot see a folder the user created and shared.

OAuth refresh token (a Google account that can write to that folder):

```sh
GOOGLE_DRIVE_FOLDER_ID=the-folder-id
GOOGLE_DRIVE_CLIENT_ID=....apps.googleusercontent.com
GOOGLE_DRIVE_CLIENT_SECRET=...
GOOGLE_DRIVE_REFRESH_TOKEN=...
```

Use the same scope, `https://www.googleapis.com/auth/drive`, when minting the refresh token. The client uploads with a resumable Drive session, writes a folder per project id, and only reports success after Drive returns a file id. This repo does not ship credentials and the QC run does not call Google.

## Character lock

A character has a name, reference images (sha256), `rightsStatus` (`owned`, `licensed`, `internal-only`, `unknown`), a rights note, locked attributes (`face`, `hair`, `outfit`, `lighting`), and a prompt prefix. The prefix is stored on each scene and prepended to the image and motion prompts in the manifest (`effectivePrompts`) and in the prompt download. `unknown` and `internal-only` set `rightsFlagged: true` in the record, the manifest, and the UI.

## Tests

```sh
npm test
npm run test:v3.2
```

`npm test` runs the existing suites and the V3.2 storage tests one file at a time. `test:v3.2` repeats storage and runs the real-clip QC: build a 3-scene source from the uploaded portrait clips, save, wipe `DATA_DIR`, restore from the local store and from a bundle, then re-export and compare ffprobe, SSIM, and PSNR. The clips are not committed. Point `V32_FIXTURE_DIR` at them if they are not in the agent uploads directory.

Measured results from the latest run are in `docs/V3_2_QC_REPORT.md`.
